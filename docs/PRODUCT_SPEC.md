# 이음로그 제품 명세

## 목적

이음로그(FACTLINE)는 학교폭력 상담 전에 학생의 흩어진 진술과 디지털 증거를 상담 가능한 기록으로 정리한다. AI는 피해 여부, 책임, 법률 결론을 판단하지 않는다. 입력 자료에서 확인 가능한 사실을 구조화하고 부족한 정보는 질문으로 남긴다.

학생 앱의 첫 완료 기준은 Android Expo Go 실기기 흐름이다. 로컬 변경은 실기기 확인 전에 Android Metro export가 성공해야 한다.
웹과 모바일이 공유하는 React 버전은 Expo SDK 54 호환 버전으로 고정해 네이티브 중복 설치를 만들지 않는다.

## 사용자

| 역할 | 주요 기능 |
| --- | --- |
| 학생 | 기관 발급 익명 ID 로그인, 사건 메모, 증거 업로드, 질문 답변, 최종 확인, 제출, 삭제 요청 |
| 상담자 | 배정 사건 확인, 대기 사건 가져오기, 검토 시작·완료, 관계도·타임라인·증거맵 미리보기·다운로드, 학생 기록 재개방, 내부 메모, PDF 출력 |
| 기관 관리자 | 학생·상담자 계정 발급·활성 제어, 권한, 원자적 사건 배정·재배정, 기관 보관 정책, 감사 로그 관리 |
| 플랫폼 관리자 | 기관 생성·수정·보관·재활성화, 기관 관리자 준비, 전체 운영 확인 |

상담자가 PDF로 저장하는 인쇄 요약에는 익명 식별자, FactBlock, 증거 목록, 확인 필요 항목만 포함한다. 상담자 내부 메모와 법률 판단 문구는 출력하지 않는다.

## 학생 흐름

1. 긴급 상황에서는 주변 어른과 긴급 지원을 먼저 이용하도록 안내한다.
2. 학생은 사실 중심으로 짧은 사건 메모를 남긴다.
3. 이미지, PDF, 음성, 영상, 문서 파일을 등록한다.
4. 등록 직후 다음 단계로 이동하고 Realtime 알림과 polling fallback으로 파일별 처리 상태를 확인한다.
5. 누락 날짜, 장소, 인물, 행위, 증거는 질문 카드로 보완한다.
6. 학생이 최종 내용을 확인한 뒤 제출한다.
7. 제출 후 기록은 잠기며 상담자가 재개방하면 다시 수정할 수 있다.

분석 뒤 사건 메모를 다시 수정하면 기존 FactBlock은 제출할 수 없다. 학생이 다시 기록 정리를 실행하고 새 FactBlock을 확인한 뒤 제출한다.
앱을 다시 열어도 학생이 제출한 최신 실제 사건은 잠금 화면으로 복원한다. 학생은 상담자 재개방 여부를 확인해 기존 기록 수정으로 돌아가거나 새 기록 작성을 명시적으로 선택한다.

## 파일 정책

- 파일당 최대 `50MB`, 사건당 최대 `50개`
- 이미지·PDF는 OCR 대상
- 음성은 `15분` 이하이면서 OpenAI STT 요청 기준 `25MB` 이하일 때 STT 대상
- 음성 길이를 확인할 수 없으면 외부 STT로 보내지 않고 상담자 직접 확인 대상으로 남김
- 영상과 일반 문서는 저장, 미리보기 또는 다운로드만 제공
- 삭제 요청은 즉시 숨김 처리하고 기본 `7일` 복구 기간 후 영구 삭제
- 영구 삭제 뒤에는 기존 사건 감사 흔적을 제거하고 기관 범위의 삭제 완료 시각과 행위만 남김
- purge worker는 사건별 lease를 원자적으로 잡고 Storage 제거 뒤 구조화 데이터 삭제와 최소 감사 로그 기록을 한 트랜잭션으로 확정한다. 중단된 lease는 `10분` 뒤 다시 회수한다.
- 기관 기본 보관 기간은 설정 가능하며 합성 seed는 `30일`
- 기관 보관 기간이 지난 사건도 purge worker가 원본 파일과 구조화 데이터를 제거하고 기관 범위의 만료 삭제 완료 기록만 남김
- 로컬과 명시적으로 허용한 격리 hosted 시연의 합성 seed는 사건별 관계도와 FactBlock-증거 연결을 포함한 완결된 가상 사건으로 유지
- 파일 PUT 전송이 실패하면 앱은 접수 대기 중인 업로드 예약을 정리한다. 서버는 학생 소유, 편집 가능한 사건, `queued`, 처리 작업 부재를 원자적으로 다시 확인하고 메타데이터를 먼저 숨긴 뒤 부분 Storage 객체와 예약을 제거한다.
- 여러 파일을 한 번에 선택한 경우 일부 파일 업로드가 실패해도 나머지 파일 등록은 계속 진행하고, 실패 개수만 학생에게 알린다.
- 같은 증거의 처리 접수가 반복되어도 서버는 증거 행 잠금 안에서 하나의 durable 작업만 만든다. 처리 예약 뒤에는 업로드 정리를 허용하지 않는다.
- `queued` 또는 `processing` 증거가 남아 있으면 학생 확인 화면과 제출 RPC가 모두 제출을 잠근다. 처리가 끝난 결과를 확인한 뒤에만 기록을 제출한다.

## 안전 원칙

- 첫 MVP는 완전한 합성 데이터만 외부 AI에 전송한다.
- 실제 학생 자료는 기본적으로 외부 AI 전송을 차단하고 상담자 직접 확인 상태로 남긴다.
- 실제 운영 전에는 보호자·기관 동의, 법률 검토, 연령별 안내, ZDR 승인과 운영 절차를 별도로 완료해야 한다.
- AI 출력은 상담자 검토를 거치며 원본 자료에 접근할 수 있어야 한다.
- Edge Function은 화면별로 선언된 HTTP 메서드만 허용하고 예상 밖 요청은 `405`로 거절한다.
- SDK 54 Expo Go 검증 기간에는 툴체인 보안 경고를 추적하고, 메이저 SDK 업그레이드는 별도 호환성 검증 뒤 적용한다.
- Android 실기기 배포 준비에서는 LAN URL과 publishable key 또는 legacy anon key만 앱에 기록하고 secret key, service role key, cron secret은 Edge Functions와 서버 경계에만 둔다.
- Android Expo Go 검증 실행은 LAN 공개 env 생성 뒤 Expo CLI의 `--lan`, `--clear` 옵션을 모바일 워크스페이스까지 전달한다.
- Expo CLI가 생성하는 모바일 타입 참조 파일은 소스가 아니라 git 무시 생성물로 취급한다.
- Android Expo Go 수동 흐름 전에 공개 env, LAN Supabase health, Metro LAN status를 자동 검사하고 접속 URL을 확인한다.
- Android Expo Go 수동 흐름은 기기·Expo Go 버전, 단계별 결과, 상담자 재개방 뒤 수정 가능 여부를 검증 기록에 남긴다.
- 작은 Android 화면에서도 로그인과 제출 완료 화면을 스크롤할 수 있어야 한다. 작성 화면은 키보드가 열린 상태에서도 현재 입력과 하단 이동 동작을 확인할 수 있게 유지한다.
- Android 앱 빌드는 민감한 학생 기록의 OS 백업을 끄고 소프트웨어 키보드 레이아웃을 `resize`로 고정한다. 음성 길이 확인은 재생 경로만 사용하며 녹음과 마이크 권한 요청은 비활성화한다.
- EAS preview APK를 내려받은 뒤 native manifest에서 앱 데이터 백업 비활성, 키보드 `adjustResize`, 녹음 권한 부재를 다시 확인한다.
- 웹 시연 실행의 Vite host 옵션도 워크스페이스까지 전달해 로컬 검증 주소를 재현 가능하게 유지한다.
- 직원 웹 로컬 연결 검증은 Supabase URL과 publishable key 또는 legacy anon key만 무시 대상 공개 env에 기록하고, Auth health와 Vite 진입 HTML을 확인한다.
- 직원 웹 UI 스모크는 상담자, 기관 관리자, 플랫폼 관리자 seed 로그인을 순서대로 수행한다. 상담자 증거 연결, 기관 관리자 기본 `30일` 보관 정책과 `7일` 삭제 복구 기간, 플랫폼 관리자 기관 관리 메뉴를 확인하고 실패 화면을 남긴다.
- 기관 관리자 보관 정책 입력은 카드 너비 안에서 줄어들고, 좁은 화면에서는 한 열로 배치한다.

## 입력 길이와 세션 안정성

- 학생 사건 메모는 최대 `1000자`다. 모바일 입력과 DB 제약이 같은 한도를 강제한다.
- 학생 앱과 상담자·관리자 웹은 저장된 refresh token으로 만료 직전 세션을 갱신한다. 장시간 작성과 상담 중 토큰 만료로 작업 흐름이 끊기지 않도록 한다.
- 상담자 사건 검색은 익명 식별자와 사건 코드를 필터링한다. 관계도는 저장된 관계 간선과 간접 관계 표시를 사용한다.
- OpenAI 키 사용 경로는 합성 자료 전용 Edge 테스트에서 이미지 vision `input_image`, PDF `input_file`, 음성 STT stub 응답을 검증한다. hosted 배포 템플릿은 공식 OpenAI endpoint를 유지한다.
- SecureStore 텍스트 초안은 작은 청크로 저장하고 읽기 전에 메모 길이·단계·날짜·청크 개수를 검증한다. 손상된 청크는 앱 진입을 막지 않고 정리한다.
- 복구된 SecureStore 메모가 서버 메모보다 최신이면 기존 FactBlock 제출을 화면에서도 즉시 잠그고 재분석을 요구한다.
- 서버와 기기 메모가 같으면 기기의 현재 단계만 복원한다. 메모가 다르면 기기 초안의 저장 시각이 서버보다 최신일 때만 복원하고, 오래된 기기 초안이 최신 서버 메모를 덮어쓰지 않게 정리한다.
- CI는 Windows PowerShell 기반 readiness와 Android export를 실행해 로컬 검증 계약을 그대로 반복한다.
- 기기 SecureStore 자동 저장·복구는 서버 제출과 분리한다. 로컬 초안 삭제 실패가 이미 완료된 제출을 실패처럼 보이게 만들지 않는다.
- 증거 bucket은 private이며 원본 객체 직접 URL 접근은 허용하지 않는다. 앱과 웹은 권한 확인 뒤 발급된 짧은 수명의 서명 URL만 사용한다.
- 사용자 비활성화와 기관 보관은 즉시 접근 차단으로 취급한다. 기존 JWT가 남아 있어도 학생 로그인, 직원 RLS 조회, 직원 Edge Function 작업을 허용하지 않는다.
- 보관 기관에는 새 사용자를 발급하지 않는다. 실패했거나 `10분` 넘게 멈춘 증거 처리 작업은 원자적으로 재접수하며 최대 `3회` 시도 뒤에는 자동 재접수하지 않는다.
- 상담자는 구조화 결과를 조회하고 내부 메모를 추가하지만 FactBlock·사람·관계·증거·질문을 직접 REST로 변조하지 않는다. 학생은 본인 검토 단계의 누락 질문 답변만 수정한다.
- 상담자 증거맵은 저장된 FactBlock-증거 연결을 그대로 표시한다. 연결이 없는 파일에 임의 진술 번호를 붙이지 않고 상담자 확인 대상으로 남긴다.
- 학생 삭제 요청은 즉시 실행하기 전에 `7일` 복구 기간과 원본 제거 영향을 한 번 더 확인한다.
- 플랫폼 관리자 화면은 대상 기관이 정해지지 않은 상태에서 기관 전용 보관 정책 저장 UI를 노출하지 않는다.
- 학생 앱은 FactBlock 후보가 준비되기 전 분석 단계에서 다음으로 넘어가지 않으며, 분석·제출 요청 중에는 같은 동작 버튼을 잠근다.
- 누락 질문 답변은 입력 즉시 화면 로컬 초안에 반영한다. polling으로 이전 서버 값이 도착해도 작성 중 답변을 덮어쓰지 않고, 입력 종료 시 연결 서버에 저장한다. 질문 카드에는 수정 중·저장 중·저장 완료·실패 상태를 표시한다. 저장이 끝나지 않은 문장이 있으면 다음 단계와 제출을 잠그고, 실패 시 입력을 보존해 재시도하거나 서버 값으로 되돌릴 수 있다. 저장 요청 중 문장을 다시 고치면 이전 요청 결과는 무효화한다. 메모 재분석을 시작하면 이전 질문 초안은 비운다.
- 학생 메모의 background PATCH와 기기 SecureStore 초안 write·clear는 `MemoUpdateQueue`로 직렬화한다. 분석은 최신 서버 메모 저장을 기다린다. 제출은 동기 ref 가드로 연속 탭을 막고 새 기기 자동 저장 예약을 멈춘다. 서버 제출 성공 뒤 기존 기기 write 다음에 clear를 실행한다. 서버 제출은 남은 PATCH 대기열을 비운 뒤 트랜잭션 RPC를 호출한다.
- 메모 기반 FactBlock 재정리는 학생 본인만 실행한다. 삭제 예약 사건은 일반 상담 재개방 작업으로 되살리지 않는다.
- 직원 웹은 로그인 직후와 snapshot 복구 시 활성 프로필·활성 기관을 확인한다. 비활성 직원은 남은 Auth 세션을 로컬에서 제거하고 보관 기관은 신규 사용자 선택 목록에서 제외한다.
- hosted 합성 bootstrap은 운영 데이터 프로젝트와 분리한 격리 시연 프로젝트에서만 명시적으로 실행한다. hosted 시연 비밀번호는 git 무시 환경 파일에서 주입하고 로컬 기본 비밀번호를 재사용하지 않는다.
- hosted 합성 bootstrap을 다시 실행하면 고정 가상 계정의 비밀번호도 현재 무시 대상 환경 파일 값으로 회전한다.
- hosted smoke는 Windows PowerShell의 서명 다운로드 응답이 문자열 또는 UTF-8 바이트 배열인 경우를 모두 검증한다.
- 로컬 Supabase 공개 클라이언트 설정은 CLI의 `PUBLISHABLE_KEY`를 우선 사용하고 구형 CLI에서만 `ANON_KEY`로 fallback한다. 서버 검증은 `SECRET_KEY`를 우선 사용하고 구형 `SERVICE_ROLE_KEY`를 fallback으로 허용한다.
- Supabase CLI는 서비스 이미지와 DB 스키마 조합을 재현할 수 있도록 루트 devDependency의 정확한 버전으로 고정한다.
